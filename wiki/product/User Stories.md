## EP-1. 기반과 디자인 시스템 (Phase 0 + Phase 1)

### US-01. LAN 백엔드에 붙는 APK
**DEV로서** 개발 PC에서 돌고 있는 Spring/OCR 서버에 실기기 APK가 붙게 하고 싶다, **클라우드 배포 없이 실제 데이터로 개발하기 위해.**
FR: FR-004, FR-006, FR-007

- **US-01-A1** — Given 개발 PC가 `192.168.x.x`에서 Spring(:8080), OCR(:8000)을 실행 중이고, When 해당 LAN IP로 빌드된 dev APK를 같은 Wi-Fi의 실기기에서 실행하면, Then 앱이 `GET /auth/me` 또는 임의 헬스체크에 HTTP 응답을 받는다.
- **US-01-A2** — Given API Base와 이미지 Base가 서로 다른 포트라면, When 문서 이미지를 렌더할 때, Then 이미지 요청은 `:8000`으로, 데이터 요청은 `:8080`으로 각각 나간다.
- **US-01-A3** — Given release 프로파일로 빌드한 APK라면, When `http://` 주소로 요청하면, Then 요청이 차단되고(cleartext 금지) 앱은 크래시 없이 네트워크 에러 화면을 보여준다.
- **US-01-A4** — Given 잘못된 IP가 주입된 빌드라면, When 앱을 실행하면, Then 무한 로딩이 아니라 15초 내 "서버에 연결할 수 없습니다" 상태로 떨어진다.

### US-02. 한 손으로 닿는 하단 내비게이션
**지훈으로서** 앱의 주요 기능을 엄지로 닿는 하단에서 전환하고 싶다, **명함을 들고 한 손으로 조작하기 위해.**
FR: FR-009, FR-099

- **US-02-A1** — Given 로그인 상태라면, When 앱을 실행하면, Then 하단에 홈·보관함·(스캔)·검색·설정 5슬롯이 보이고 홈이 선택되어 있다. 가운데 스캔은 탭이 아니라 강조 액션 버튼이다.
- **US-02-A2** — Given 보관함 탭에서 3단계 깊이까지 들어간 상태라면, When 홈 탭으로 갔다가 보관함 탭으로 돌아오면, Then 이전 깊이와 스크롤 위치가 그대로 복원된다.
- **US-02-A3** — Given 탭 루트 화면이라면, When 하드웨어 뒤로가기를 누르면, Then 홈 탭으로 이동하고, 홈 탭 루트에서 다시 누르면 `한 번 더 누르면 종료됩니다` 토스트가 뜬다.
- **US-02-A4** — Given 탭 전환 조작을 했다면, When 300ms가 경과하면, Then 대상 화면의 첫 콘텐츠 프레임이 이미 그려져 있다.

### US-03. 알림창이 아니라 토스트
**서연으로서** 실패·성공 안내를 화면 흐름을 끊지 않고 받고 싶다, **작업을 계속 이어가기 위해.**
FR: FR-016, FR-018, FR-103

- **US-03-A1** — Given 임의의 서버 오류가 발생했다면, When 앱이 이를 표시할 때, Then 시스템 다이얼로그가 아니라 하단 토스트로 뜨고 3초 후 자동 소멸한다.
- **US-03-A2** — Given 서버가 한글·영어 혼재 에러 문자열을 내려줬다면, When 앱이 이를 표시할 때, Then 서버 문자열이 아니라 HTTP status 기반의 앱 문구가 노출된다.
- **US-03-A3** — Given 짧은 시간에 오류가 3건 발생했다면, When 토스트를 표시할 때, Then 동시에 1개만 보이고 나머지는 큐에 쌓여 순차 표시된다.
- **US-03-A4** — Given 목록이 비어 있다면, When 화면이 로딩을 마치면, Then 아이콘 + 안내 문구 + CTA 버튼을 갖춘 빈 상태가 표시된다(회색 텍스트 한 줄만 있는 원본 방식 금지).

### US-04. 어디서나 읽히는 화면 — 라이트와 다크 양쪽에서
**하은으로서** 밝은 야외와 어두운 실내 모두에서 글자를 읽고 싶다, **낮에는 게시판 앞에서, 밤에는 불 꺼진 방에서 같은 앱을 쓰기 위해.**
FR: FR-011, FR-012, FR-019, FR-112, FR-124, FR-126, FR-127 / NFR-021, NFR-023, NFR-027, NFR-029

- **US-04-A1** — Given OS가 다크모드이고 테마 설정이 기본값(`시스템 따름`)이라면, When 앱을 실행하면, Then 앱 **전체가 다크 테마로** 렌더되고(흰 화면 프레임 0회), 액션시트·날짜피커·키보드 같은 네이티브 컴포넌트도 함께 다크로 뜬다.
- **US-04-A2** — Given 앱을 켜 둔 상태라면, When OS 테마를 라이트↔다크로 바꾸면, Then 300ms 내 앱이 따라 전환되고 보고 있던 화면·스크롤 위치가 그대로 유지된다.
- **US-04-A3** — Given 임의의 텍스트/배경 조합이라면, When **두 테마 각각** 명도 대비를 측정하면, Then 본문 4.5:1 이상, 큰 텍스트·비텍스트 경계 3:1 이상이다(라이트 기준면 `#FFFFFF`, 다크 기준면 `#0F1621`, 카드·입력 위 조합은 그 표면 기준으로 계산).
- **US-04-A4** — Given 다크 테마라면, When 채움 버튼(`저장`·`제출`)을 보면, Then 라벨이 흰색이 아니라 어두운 `text.inverse`로 렌더되어 읽힌다(밝은 액션 컨테이너 위 흰 글자는 2.78:1로 무너지기 때문).
- **US-04-A5** — Given 다크 테마로 명함 목록을 본다면, When 썸네일을 보면, Then 흰 종이 이미지가 배경에 직접 닿지 않고 프레임 + 매트로 감싸여 있으며, 이미지 자체에는 어둡게 하는 필터가 걸려 있지 않다(문서 글자가 원본 그대로 판독된다).
- **US-04-A6** — Given 다크 테마로 스캔 결과 확인 화면(SCR-12)에 있다면, When 이미지 영역을 보면, Then 그 영역만 라이트 표면을 유지해 흰 문서와의 대비 충격이 없다(의도된 국소 예외).
- **US-04-A7** — Given OS 글꼴 크기를 130%로 올렸다면, When 31개 화면을 **두 테마로** 순회하면, Then 잘림·겹침이 0건이다.
- **US-04-A8** — Given 임의의 탭 가능한 요소라면, When 터치 영역을 측정하면, Then 44dp 이상이다.

## EP-2. 인증과 세션 (Phase 2)

### US-05. 한 번 로그인하면 계속 로그인
**지훈으로서** 앱을 열 때마다 로그인하지 않고 싶다, **명함을 받은 10초 안에 촬영을 끝내기 위해.**
FR: FR-028, FR-029, FR-031

- **US-05-A1** — Given 지난주에 로그인했고 토큰이 아직 유효하다면, When 앱을 실행하면, Then 로그인 화면을 거치지 않고 홈에 도달한다.
- **US-05-A2** — Given 저장된 토큰이 만료됐다면, When 앱을 실행하면, Then 스플래시에서 곧장 로그인 화면으로 가고 중간에 홈이 잠깐 보이는 깜빡임이 없다.
- **US-05-A3** — Given 앱을 백그라운드로 5분 이상 두었다면, When 다시 포그라운드로 돌아오면, Then `GET /auth/me` 세션 검증이 1회 수행된다.
- **US-05-A4** — Given 백그라운드 체류가 5분 미만이라면, When 포그라운드로 복귀하면, Then 세션 검증 API를 호출하지 않는다.
- **US-05-A5** — Given 기기 파일시스템을 덤프했다면, When JWT 문자열을 검색하면, Then 평문으로 발견되지 않는다.

### US-06. 이메일로 시작하기
**서연으로서** 이메일과 비밀번호만으로 가입·로그인하고 싶다, **소셜 계정을 연결하고 싶지 않기 때문에.**
FR: FR-022, FR-023, FR-024, FR-034

- **US-06-A1** — Given 유효한 이메일과 8자 이상 비밀번호를 입력했다면, When 가입 버튼을 누르면, Then 가입과 동시에 로그인되어 홈에 도달한다.
- **US-06-A2** — Given 이미 존재하는 이메일이라면, When 가입을 시도하면, Then 폼 하단에 실패 사유가 인라인으로 표시되고 입력값은 유지된다.
- **US-06-A3** — Given 이메일 형식이 잘못됐거나 비밀번호가 8자 미만이라면, When 폼을 보면, Then 제출 버튼이 비활성 상태이고 서버 요청이 나가지 않는다.
- **US-06-A4** — Given 가입이 성공했다면, When 닉네임 설정 단계가 뜨면, Then 입력 후 저장 시 홈 헤더 이름이 즉시 바뀌고, 건너뛰기를 눌러도 홈에 도달한다.

### US-07. 소셜 로그인이 앱 안에서 끝난다
**하은으로서** 구글 계정으로 로그인하고 다시 앱으로 돌아오고 싶다, **브라우저를 수동으로 닫고 앱을 다시 찾는 번거로움 없이.**
FR: FR-025, FR-026, FR-027 / NFR-017

- **US-07-A1** — Given 로그인 화면이라면, When 구글/카카오/네이버 버튼을 누르면, Then 외부 브라우저 앱이 아니라 인앱 브라우저 탭이 열린다.
- **US-07-A2** — Given 제공자 동의를 완료했다면, When 콜백이 발생하면, Then 인앱 탭이 자동으로 닫히고 앱이 로그인 상태로 홈에 도달한다.
- **US-07-A3** — Given 동의 화면에서 취소를 눌렀다면, When 앱으로 돌아오면, Then 로딩이 해제되고 로그인 화면이 조작 가능한 상태로 남는다.
- **US-07-A4** — Given 콜백이 90초 동안 오지 않았다면, When 대기가 끝나면, Then 자동 취소되고 재시도 안내 토스트가 뜬다.
- **US-07-A5** — Given 조작된 딥링크로 위조 토큰이 전달됐다면, When 앱이 이를 수신하면, Then 형식·만료 검증에 실패해 저장하지 않고 로그인 화면을 유지한다.

### US-08. 세션이 끊기면 즉시 알려준다
**지훈으로서** 토큰이 만료되면 바로 알고 재로그인하고 싶다, **저장한 줄 알았던 명함이 실제로는 안 저장되는 일을 막기 위해.**
FR: FR-030, FR-033

- **US-08-A1** — Given 토큰이 만료된 상태라면, When 임의의 인증 API를 호출하면, Then 401 또는 400 응답을 세션 만료로 판정해 로그인 화면으로 이동한다.
- **US-08-A2** — Given 세션 만료로 로그아웃됐다면, When 화면이 전환되면, Then `로그인 세션이 만료되었습니다. 다시 로그인해 주세요.` 토스트가 1회만 표시된다(동시 실패 요청 N건이어도 중복 표시 없음).
- **US-08-A3** — Given 세션이 만료됐고 사용자가 편집 중이던 폼이 있다면, When 재로그인을 마치면, Then 편집 중이던 내용이 복원되거나 최소한 손실 사실이 명시된다.
- **US-08-A4** — Given 로그아웃 상태라면, When 하드웨어 뒤로가기로 이전 화면 복귀를 시도하면, Then 인증 화면 밖으로 나가지 않는다.

### US-09. 처음 쓰는 사람에게 3화면으로 설명
**하은으로서** 앱이 뭘 하는지 30초 안에 이해하고 싶다, **가입할지 결정하기 위해.**
FR: FR-021

- **US-09-A1** — Given 앱 최초 실행이라면, When 스플래시가 끝나면, Then 스와이프 가능한 온보딩 슬라이드가 표시된다.
- **US-09-A2** — Given 온보딩을 1회 완료했거나 건너뛰었다면, When 앱을 다시 실행하면, Then 온보딩이 다시 표시되지 않는다.
- **US-09-A3** — Given 온보딩 마지막 슬라이드라면, When CTA를 누르면, Then 회원가입 화면으로 이동하고, 하단 링크로 로그인 화면에도 갈 수 있다.

### US-10. 안전한 로그아웃
**서연으로서** 기기를 빌려줄 때 로그아웃하고 싶다, **내 문서가 노출되지 않게 하기 위해.**
FR: FR-032

- **US-10-A1** — Given 설정 화면이라면, When 로그아웃을 누르면, Then 확인 다이얼로그가 뜨고 취소하면 아무 일도 일어나지 않는다.
- **US-10-A2** — Given 로그아웃을 확정했다면, When 앱을 완전히 종료 후 재실행하면, Then 로그인 화면이 표시된다.
- **US-10-A3** — Given 로그아웃했다면, When SecureStore를 조회하면, Then 토큰·사용자 정보 키가 삭제되어 있다.

## EP-3. 찍으면 저장되는 스캔 (Phase 3)

### US-11. 탭 한 번으로 카메라
**지훈으로서** 스캔 탭을 누르는 즉시 촬영할 수 있길 원한다, **상대와 헤어진 직후 10초 안에 끝내기 위해.**
FR: FR-035, FR-036 / NFR-007

- **US-11-A1** — Given 카메라 권한이 이미 허용됐다면, When 스캔 탭을 누르면, Then 1.5초(P90) 내 프리뷰가 표시된다.
- **US-11-A2** — Given 카메라 권한이 미결정 상태라면, When 스캔 탭을 처음 누르면, Then 권한이 왜 필요한지 설명하는 화면을 먼저 보여준 뒤 시스템 권한 팝업을 띄운다.
- **US-11-A3** — Given 권한을 영구 거부했다면, When 스캔 탭에 들어가면, Then 설정 앱으로 이동하는 버튼이 있는 안내 화면이 표시된다.
- **US-11-A4** — Given 프리뷰 상태라면, When 셔터를 누르면, Then 햅틱 피드백과 함께 촬영되고 즉시 다음 단계로 넘어간다.

### US-12. 앨범에 이미 있는 사진도
**서연으로서** 이미 찍어둔 영수증 사진을 앱에 넣고 싶다, **과거 것부터 정리하기 위해.**
FR: FR-037, FR-038, FR-052

- **US-12-A1** — Given 스캔 화면이라면, When 앨범 버튼을 누르면, Then 시스템 이미지 피커가 열리고 선택 후 크롭 단계로 진입한다.
- **US-12-A2** — Given 갤러리 앱에서 이미지를 보고 있다면, When 공유 → MORA를 선택하면, Then 앱이 실행되고 해당 이미지로 크롭 단계에 진입한다.
- **US-12-A3** — Given 기울어진 사진이라면, When 크롭 화면에서 90° 회전과 영역 조정을 하면, Then 조정 결과가 다음 단계에 반영된다.
- **US-12-A4** — Given 이미지가 아닌 파일이 공유로 들어왔다면, When 앱이 이를 수신하면, Then 크래시 없이 "이미지 파일만 처리할 수 있습니다" 안내를 표시한다.

### US-13. 무거운 사진도 빠르게 올라간다
**지훈으로서** 12MP 원본을 찍어도 업로드가 빠르길 원한다, **행사장 혼잡한 네트워크에서도 실패하지 않기 위해.**
FR: FR-039, FR-040, FR-041 / NFR-005, GUARD-2

- **US-13-A1** — Given 5MB짜리 12MP 사진을 촬영했다면, When 업로드가 시작되면, Then 실제 전송 크기가 1.5MB 이하다.
- **US-13-A2** — Given 업로드가 진행 중이라면, When 화면을 보면, Then 300ms 내 진행 표시가 나타나고 `업로드 중 → 텍스트 인식 중 → 정보 구조화 중` 단계가 갱신된다.
- **US-13-A3** — Given 업로드/스캔이 진행 중이라면, When 취소를 누르면, Then 요청이 즉시 중단되고 카메라 초기 상태로 복귀한다.
- **US-13-A4** — Given 서버가 60초 동안 응답하지 않는다면, When 타임아웃이 발생하면, Then 재시도 버튼이 있는 에러 상태로 전환되고 앱이 멈추지 않는다.

### US-14. 저장 전에 반드시 확인시켜 준다
**하은으로서** OCR이 읽은 값을 저장 전에 고치고 싶다, **마감일이 잘못 저장되는 것을 막기 위해.**
FR: FR-043, FR-044, FR-045, FR-046

- **US-14-A1** — Given 스캔이 완료됐다면, When 결과 화면을 보면, Then 문서 유형 배지와 신뢰도(%)가 표시되고 추출된 필드가 편집 가능한 폼으로 나열된다.
- **US-14-A2** — Given 자동 분류가 틀렸다면, When 문서 유형을 바꾸면, Then 새 유형의 필드 스키마로 폼이 교체되고 공통 필드(전화·이메일·웹사이트)의 값이 승계된다.
- **US-14-A3** — Given 어떤 값이 맞는지 확신이 안 선다면, When OCR 원문 블록을 탭하면, Then 이미지 위 해당 위치에 박스가 표시되고 이미지 영역으로 스크롤된다.
- **US-14-A4** — Given 티켓으로 자동 분류됐다면, When 신뢰도 영역을 보면, Then 키워드 기반 감지임이 병기된다(하드코딩 1.0을 정확도로 오인시키지 않는다).
- **US-14-A5** — Given 유형이 `기타`로 분류됐다면, When 저장을 시도하면, Then 저장 버튼이 비활성이고 4종 중 하나를 선택하라는 안내가 표시된다.

### US-15. 저장은 실패하거나 성공하거나, 애매하지 않게
**서연으로서** 저장이 끝났는지 확실히 알고 싶다, **같은 영수증을 두 번 찍는 일을 막기 위해.**
FR: FR-047, FR-048, FR-049 / NFR-011, NFR-012

- **US-15-A1** — Given 확인 화면에서 저장을 눌렀다면, When 이미지 커밋과 문서 저장이 모두 성공하면, Then 성공 피드백이 뜨고 목록에 즉시 반영된다.
- **US-15-A2** — Given 이미지 커밋에 실패했다면, When 앱이 이를 감지하면, Then 문서 저장을 진행하지 않고 재시도를 제안한다(이미지 없는 레코드를 만들지 않는다).
- **US-15-A3** — Given 저장 버튼을 20회 연타했다면, When 서버 레코드를 확인하면, Then 1건만 생성되어 있다.
- **US-15-A4** — Given 저장은 성공했지만 서버가 경고 메시지를 함께 보냈다면, When 결과 화면을 보면, Then 성공으로 처리하되 경고 배너가 함께 표시된다.
- **US-15-A5** — Given 저장이 네트워크 오류로 실패했다면, When 화면을 보면, Then 입력했던 필드 값이 100% 그대로 남아 있고 재시도가 가능하다.

### US-16. 명함 7장을 연속으로
**지훈으로서** 저장 후 곧바로 다음 장을 찍고 싶다, **부스 앞에서 흐름이 끊기지 않기 위해.**
FR: FR-051

- **US-16-A1** — Given 방금 저장을 마쳤다면, When 성공 피드백이 사라지면, Then 카메라 프리뷰로 자동 복귀한다.
- **US-16-A2** — Given 연속으로 3건을 저장했다면, When 화면 상단을 보면, Then `저장됨 3건` 카운터가 표시된다.
- **US-16-A3** — Given 스캔 탭을 벗어났다가 돌아왔다면, When 화면을 보면, Then 세션 카운터가 초기화되어 있다.

### US-17. 영수증 품목까지 놓치지 않기
**서연으로서** 영수증의 상호·날짜·총액이 정확히 들어가길 원한다, **정산 엑셀에 그대로 옮기기 위해.**
FR: FR-045, FR-048

- **US-17-A1** — Given 영수증으로 분류됐다면, When 확인 화면을 보면, Then `업체 이름 / 구매일자 / 합계금액` 3필드가 표시되고 전부 편집 가능하다.
- **US-17-A2** — Given 총액이 `₩12,500` 같은 형식으로 인식됐다면, When 저장하면, Then 숫자만 추출된 값이 서버에 전송된다.
- **US-17-A3** — Given OCR이 뽑지 못한 필드(주소·결제수단·카드사 등)가 있다면, When 확인 화면을 보면, Then 해당 필드가 빈 값으로 노출되어 직접 입력할 수 있다.

## EP-4. 보관함에서 다시 찾기 (Phase 4)

### US-18. 한 화면에서 4종을 오간다
**하은으로서** 명함·포스터·영수증·티켓을 탭 하나 안에서 전환하고 싶다, **메뉴를 헤매지 않기 위해.**
FR: FR-053, FR-060, FR-067

- **US-18-A1** — Given 보관함 탭이라면, When 화면 상단을 보면, Then `전체·명함·포스터·영수증·티켓` 가로 스크롤 칩이 있고 선택 상태가 시각적으로 구분된다.
- **US-18-A2** — Given 명함 목록을 300px 스크롤한 상태에서 포스터로 전환했다가 돌아오면, When 명함 목록을 보면, Then 이전 스크롤 위치가 유지된다.
- **US-18-A3** — Given 보기 방식을 그리드로 바꿨다면, When 앱을 재시작하면, Then 그리드 설정이 유지된다.
- **US-18-A4** — Given 정렬을 `오래된 순`으로 바꿨다면, When 목록을 보면, Then 등록일 오름차순으로 즉시 재정렬된다.

### US-19. 20건 넘어도 다 보인다
**지훈으로서** 저장한 명함을 전부 보고 싶다, **1년치 명함을 관리하기 위해.**
FR: FR-054 ~ FR-059 / NFR-003

- **US-19-A1** — Given 저장된 명함이 120건이라면, When 목록을 끝까지 스크롤하면, Then 120건 전부 열람 가능하다(원본 웹은 20건에서 잘렸다).
- **US-19-A2** — Given 목록 하단에 접근 중이라면, When 남은 스크롤이 200px 이하가 되면, Then 다음 페이지가 자동 요청되고 중복 요청은 발생하지 않는다.
- **US-19-A3** — Given 마지막 페이지에 도달했다면, When 더 스크롤하면, Then 로딩 인디케이터가 사라지고 추가 요청이 없다.
- **US-19-A4** — Given 목록을 아래로 당겼다면, When 손을 떼면, Then 햅틱과 함께 첫 페이지가 재조회되고 목록이 갱신된다.
- **US-19-A5** — Given 500건 목록을 빠르게 스크롤한다면, When 프레임률을 측정하면, Then 드롭 프레임이 1% 이하다.

### US-20. 상세를 열고 바로 고친다
**서연으로서** 잘못 저장된 값을 목록에서 바로 고치고 싶다, **다시 찍지 않기 위해.**
FR: FR-061, FR-062

- **US-20-A1** — Given 목록의 항목을 탭했다면, When 상세가 열리면, Then 원본 이미지와 필드 목록이 보이고 아래로 끌어 닫을 수 있다.
- **US-20-A2** — Given 상세에서 편집 모드로 전환했다면, When 필드를 수정하고 저장하면, Then 상세와 목록이 동시에 갱신된다.
- **US-20-A3** — Given 영수증 상세라면, When 편집 후 저장하면, Then 실제로 저장이 완료된다(원본 웹은 API 호출 자체가 없어 영구 로딩이었다).
- **US-20-A4** — Given 편집 중 키보드가 올라왔다면, When 하단 필드를 탭하면, Then 입력 필드가 키보드에 가리지 않는다.

### US-21. 삭제는 실수해도 되돌릴 수 있게
**하은으로서** 잘못 삭제하는 사고를 피하고 싶다, **한 번의 오터치로 기록을 잃지 않기 위해.**
FR: FR-063, FR-105

- **US-21-A1** — Given 목록 항목을 왼쪽으로 스와이프했다면, When 임계값을 넘겨 놓으면, Then 삭제 확인 다이얼로그가 뜬다(임계값 미만이면 원위치 복귀).
- **US-21-A2** — Given 삭제를 확정했다면, When 목록을 보면, Then 항목이 즉시 사라진다(낙관적 제거).
- **US-21-A3** — Given 서버 삭제가 실패했다면, When 응답을 받으면, Then 항목이 원위치로 복원되고 실패 토스트가 뜬다.
- **US-21-A4** — Given 삭제 다이얼로그라면, When 확인 버튼을 보면, Then 파괴적 액션 스타일(destructive)로 표시된다.

### US-22. 명함첩으로 묶어 관리
**지훈으로서** 명함을 행사별·거래처별로 묶고 싶다, **나중에 그룹 단위로 찾기 위해.**
FR: FR-064, FR-065

- **US-22-A1** — Given 명함 목록이라면, When 그룹 목록을 열면, Then `전체 명함`·`미분류`·사용자 그룹이 표시되고 각각 선택 시 목록이 필터링된다.
- **US-22-A2** — Given 새 그룹을 추가하려 한다면, When 추가를 누르면, Then 시스템 prompt가 아니라 앱 입력 시트가 열리고 이름을 입력해 생성된다.
- **US-22-A3** — Given 그룹을 삭제하려 한다면, When 확인 다이얼로그를 보면, Then "그룹 안의 명함은 미분류로 이동됩니다"가 안내되고, 확정 후 해당 명함들이 미분류에 나타난다.
- **US-22-A4** — Given 명함 상세라면, When 그룹 선택 시트에서 다른 그룹을 고르면, Then 즉시 이동되고 원래 그룹 목록에서 사라진다.
- **US-22-A5** — Given 기존 그룹의 이름을 바꾸려 한다면, When 이름 변경을 실행하면, Then 서버에 반영되고 목록 라벨이 갱신된다(웹에 없던 기능).

### US-23. 원본 이미지를 크게 본다
**하은으로서** 포스터 원본을 확대해서 읽고 싶다, **작은 글씨의 신청 조건을 확인하기 위해.**
FR: FR-066, FR-068

- **US-23-A1** — Given 상세의 이미지를 탭했다면, When 뷰어가 열리면, Then 전체화면으로 이미지가 표시된다.
- **US-23-A2** — Given 뷰어라면, When 핀치 또는 더블탭을 하면, Then 최대 4배까지 확대되고 텍스트가 판독 가능하다.
- **US-23-A3** — Given 같은 이미지를 두 번째로 열었다면, When 네트워크 요청을 관찰하면, Then 요청이 발생하지 않는다(디스크 캐시 히트).
- **US-23-A4** — Given 이미지 로드에 실패했다면, When 화면을 보면, Then 깨진 아이콘이 아니라 `이미지가 없습니다` 대체 표시가 나온다.

## EP-5. 검색과 챗봇 (Phase 5)

### US-24. 기억나는 단어로 찾는다
**지훈으로서** 이름 일부나 회사명만으로 명함을 찾고 싶다, **정확한 철자를 몰라도 되기 위해.**
FR: FR-069, FR-070, FR-072, FR-073

- **US-24-A1** — Given 앱을 설치하고 처음 검색 화면에 진입했다면, When 화면이 뜨면, Then 키보드가 자동으로 올라오고 유형은 `명함`(`BUSINESS_CARD`)이 선택되어 있다.
- **US-24-A6** — Given 지난번에 `영수증`으로 검색을 실행했다면, When 검색 화면에 다시 진입하면, Then 유형이 `영수증`으로 복원되어 있다(앱을 재시작해도 유지). Given 칩만 눌러 보고 검색은 실행하지 않았다면, When 다시 진입하면, Then 이전에 **실행했던** 유형이 그대로 남아 있다.
- **US-24-A2** — Given `김대리`를 입력하고 제출했다면, When 결과가 오면, Then 관련도 순으로 카드가 표시되고 일치 구간이 강조 색으로 렌더된다.
- **US-24-A3** — Given 유형을 `영수증`으로 바꾸고 검색했다면, When 결과가 오면, Then 실제 영수증 결과가 표시된다(원본 웹은 항상 0건이었다).
- **US-24-A4** — Given 정렬을 `최신순`으로 바꿨다면, When 목록을 보면, Then 추가 서버 요청 없이 즉시 재정렬된다.
- **US-24-A5** — Given 결과가 0건이라면, When 화면을 보면, Then 빈 상태 안내와 다른 유형으로 검색해 보라는 힌트가 표시된다.

### US-25. 타이핑만으로 기록이 쌓이지 않는다
**DEV로서** 검색 기록이 무의미하게 폭증하지 않길 원한다, **사용자 데이터를 깨끗하게 유지하기 위해.**
FR: FR-071, FR-074, FR-075

- **US-25-A1** — Given 검색어를 10글자 타이핑하는 중이라면, When 네트워크를 관찰하면, Then 검색 API 호출이 0건이다.
- **US-25-A2** — Given 엔터 또는 검색 버튼을 눌렀다면, When 네트워크를 관찰하면, Then 검색 API가 정확히 1회 호출된다.
- **US-25-A3** — Given 검색어가 비어 있는 상태라면, When 검색 화면을 보면, Then 최근 검색어가 최대 10건 표시되고 탭하면 그 검색어로 재검색된다.
- **US-25-A4** — Given 검색 기록 전체 삭제를 실행했다면, When 완료되면, Then `검색 기록 N건을 삭제했습니다.` 토스트가 뜨고 최근 검색어 목록이 비워진다.

### US-26. 말하듯 물어보면 요약해 준다
**서연으로서** "3월 카페 영수증"처럼 문장으로 묻고 싶다, **일일이 필터를 조작하지 않기 위해.**
FR: FR-076, FR-077, FR-078 / NFR-006

- **US-26-A1** — Given 로그인 상태라면, When 화면 우하단을 보면, Then 챗봇 FAB가 하단 탭바 위에 떠 있고, 탭하면 전체화면 대화가 열린다.
- **US-26-A2** — Given 문서 유형을 고르지 않았다면, When 입력창을 보면, Then placeholder가 `문서 유형을 먼저 선택하세요`이고 전송 버튼이 비활성이다.
- **US-26-A3** — Given 유형 `영수증`을 선택했다면, When 입력창을 보면, Then placeholder가 `영수증에서 가게명이나 금액을 검색해보세요`로 바뀐다.
- **US-26-A4** — Given 질문을 전송했다면, When 응답 대기 중이라면, Then `답변 작성 중...` 인디케이터가 표시되고 리스트가 하단으로 자동 스크롤된다.
- **US-26-A5** — Given 60초가 지나도 응답이 없다면, When 타임아웃이 발생하면, Then 재시도 가능한 에러 메시지 버블이 표시되고 앱이 멈추지 않는다.

### US-27. 답변의 근거를 확인한다
**하은으로서** 챗봇이 어떤 문서를 보고 답했는지 알고 싶다, **답변을 믿을지 판단하기 위해.**
FR: FR-079, FR-080

- **US-27-A1** — Given 답변에 출처가 있다면, When 답변 하단을 보면, Then 출처 카드가 문서 유형 배지·제목과 함께 표시된다.
- **US-27-A2** — Given 출처 카드를 탭했다면, When 화면이 전환되면, Then 해당 문서의 상세 화면이 열린다.
- **US-27-A3** — Given 검색 결과가 0건이라 답변이 안내 문구뿐이라면, When 화면을 보면, Then 출처 영역이 표시되지 않는다.
- **US-27-A4** — Given 대화 초기화를 실행했다면, When 확인 다이얼로그에서 확정하면, Then 대화가 첫 인사말 상태로 돌아가고 유형 선택도 해제된다.

### US-40. 유형을 모를 때는 전부 뒤진다
**서연으로서** 어느 유형에 저장했는지 기억나지 않을 때 `전체`로 한 번에 찾고 싶다, **명함·영수증·티켓을 차례로 4번 검색하지 않기 위해.**
FR: FR-069, FR-130 / GUARD-6

- **US-40-A1** — Given 검색 화면이라면, When 유형 칩을 보면, Then `전체`가 첫 칩으로 존재하되 **선택되어 있지는 않다**(기본값은 마지막 사용 유형 또는 `명함`).
- **US-40-A2** — Given `전체`를 선택하고 `스타벅스`를 제출했다면, When 결과가 오면, Then 4종의 결과가 하나의 목록으로 합쳐져 표시되고 각 카드에 유형 배지가 붙어 있다.
- **US-40-A3** — Given `전체` 검색 중 일부 유형의 요청이 500으로 실패했다면, When 결과 화면을 보면, Then 성공한 유형의 결과는 그대로 노출되고 실패 사실만 별도로 안내된다(전체가 0건으로 떨어지지 않는다).
- **US-40-A4** — Given `전체`로 검색을 1회 실행했다면, When 최근 검색어 목록을 보면, Then 같은 검색어가 **1건만** 쌓여 있다(4건이 아니다).
- **US-40-A5** — Given `전체`로 검색해 서버에 기록 4건이 쌓였다면, When 전체 기록 보기 화면을 열면, Then 동일 검색어 4줄이 아니라 **1줄로 병합되어** 보인다.
- **US-40-A6** — Given `전체`로 검색한 뒤 화면을 벗어났다면, When 다시 진입하면, Then `전체`가 그대로 선택되어 있다(명시적으로 고른 선택을 명함으로 되돌리지 않는다).

## EP-6. 홈 대시보드와 설정 (Phase 6)

### US-28. 오늘 뭘 해야 하는지 홈에서 본다
**하은으로서** 앱을 열자마자 마감과 일정을 보고 싶다, **놓치는 게 없는지 5초 안에 확인하기 위해.**
FR: FR-081, FR-082, FR-083, FR-084

- **US-28-A1** — Given 홈 탭에 진입했다면, When 네트워크를 관찰하면, Then 대시보드 API가 1회만 호출된다(웹은 3회 호출 후 클라이언트 조립).
- **US-28-A2** — Given 마감 임박 문서가 있다면, When 홈을 보면, Then 가로 캐러셀에 D-Day 배지와 함께 표시되고, 3일 이내는 경고색이다.
- **US-28-A3** — Given 마감 카드를 탭했다면, When 화면이 전환되면, Then 해당 문서 상세가 열린다(원본 웹은 클릭해도 아무 일이 없었다).
- **US-28-A4** — Given 캘린더에서 좌우로 스와이프했다면, When 손을 떼면, Then 이전/다음 달로 이동한다.
- **US-28-A5** — Given 일정이 있는 날짜를 탭했다면, When 시트가 열리면, Then 그날의 일정 목록이 유형 배지와 함께 표시된다.

### US-29. 마감을 놓치지 않게 알림을 본다
**하은으로서** 마감 알림을 모아서 확인하고 싶다, **공모전 신청을 놓치지 않기 위해.**
FR: FR-085, FR-086, FR-087, FR-088

- **US-29-A1** — Given 읽지 않은 알림이 있다면, When 홈 헤더의 벨 아이콘을 보면, Then 미읽음 개수 배지가 표시된다.
- **US-29-A2** — Given 알림 목록에 진입했다면, When 화면을 보면, Then 읽음/미읽음이 시각적으로 구분되고 유형별 아이콘이 다르다.
- **US-29-A3** — Given 알림을 탭했다면, When 화면이 전환되면, Then 해당 문서 종류의 보관함으로 이동하고 그 알림이 읽음 처리된다.
- **US-29-A4** — Given 전체 읽음을 눌렀다면, When 완료되면, Then `N건을 읽음 처리했습니다` 토스트가 뜨고 배지가 사라진다.
- **US-29-A5** — Given 알림이 하나도 없다면, When 목록을 보면, Then 빈 상태 안내가 표시된다.

### US-30. 알림 설정이 기기를 바꿔도 유지된다
**서연으로서** 알림 설정을 서버에 저장하고 싶다, **앱을 다시 설치해도 그대로이길 바라기 때문에.**
FR: FR-089

- **US-30-A1** — Given 설정 화면이라면, When 마감 리마인더 일수를 3일에서 7일로 바꾸면, Then 서버에 저장된다.
- **US-30-A2** — Given 설정을 변경한 뒤 앱을 삭제·재설치하고 로그인했다면, When 설정 화면을 보면, Then 변경한 값이 그대로 표시된다.
- **US-30-A3** — Given 마감 알림 토글을 끄면, When 다음 배치가 돌면, Then 해당 유형의 알림이 생성되지 않는다.
- **US-30-A4** — Given 저장 요청이 실패했다면, When 화면을 보면, Then 토글이 원래 상태로 되돌아가고 실패 토스트가 뜬다.

### US-31. 내 계정을 내가 관리한다
**서연으로서** 닉네임·비밀번호를 바꾸고 필요하면 탈퇴하고 싶다, **내 정보를 스스로 통제하기 위해.**
FR: FR-090, FR-091, FR-092, FR-093

- **US-31-A1** — Given 설정 화면에 진입했다면, When 프로필 영역을 보면, Then 서버에서 받은 실제 닉네임·이메일·가입일이 표시된다(하드코딩 기본값 없음).
- **US-31-A2** — Given 닉네임을 2~20자 허용 문자로 입력했다면, When 저장하면, Then 즉시 반영되고, 규칙 위반 시 저장 버튼이 비활성이다.
- **US-31-A3** — Given 소셜 로그인 계정이라면, When 비밀번호 변경을 시도하면, Then 진입이 차단되고 사유가 안내된다.
- **US-31-A4** — Given 1분 내 비밀번호 변경을 6회 시도했다면, When 6번째 응답을 받으면, Then 429를 감지해 `잠시 후 다시 시도해 주세요` 안내가 뜬다.
- **US-31-A5** — Given 탈퇴를 진행한다면, When 로컬 계정이면 비밀번호를, 소셜 계정이면 `탈퇴` 문구 입력을 요구하고, 확정 후에는 저장소가 전량 파기되고 온보딩 화면으로 돌아간다.

### US-32. 일정은 구글 캘린더에도 남긴다
**지훈으로서** 티켓·포스터 일정을 구글 캘린더로 보내고 싶다, **기존 일정 관리 습관을 유지하기 위해.**
FR: FR-095, FR-096, FR-097, FR-098

- **US-32-A1** — Given 설정에서 캘린더 연동 토글을 켰다면, When 인앱 브라우저에서 구글 동의를 마치면, Then 앱으로 복귀하고 토글이 ON으로 바뀐다.
- **US-32-A2** — Given 연동 중 사용자가 취소했다면, When 앱으로 돌아오면, Then 토글이 OFF를 유지하고 실패 안내가 표시된다.
- **US-32-A3** — Given 이미 연동된 상태라면, When 토글을 끄고 확인하면, Then 연동이 해제되고 토글이 OFF가 된다.
- **US-32-A4** — Given 연동 요청이 처리 중이라면, When 토글을 다시 누르면, Then 중복 요청이 발생하지 않는다.
- **US-32-A5** — Given 앱 정보 화면이라면, When 화면을 보면, Then 버전이 런타임에서 조회된 실제 값이고, 이용약관·개인정보 처리방침이 열린다.

### US-39. 테마는 내가 고른 대로
**하은으로서** 앱 테마를 직접 고르고 그 선택이 계속 유지되길 원한다, **기기는 항상 다크로 쓰지만 사진 속 문서를 볼 때만 라이트로 보고 싶을 때도 있기 때문에.**
FR: FR-123, FR-124, FR-125, FR-126, FR-129 / NFR-027

- **US-39-A1** — Given 설정 화면이라면, When 테마 항목을 보면, Then `시스템 따름` / `라이트` / `다크` 3택 세그먼트가 있고 `시스템 따름`이 기본 선택되어 있다.
- **US-39-A2** — Given 설정에서 `다크`를 골랐다면, When 세그먼트를 탭하면, Then 300ms 내 현재 화면이 다크로 재도색되고 화면이 리마운트되거나 스크롤이 맨 위로 튀지 않는다.
- **US-39-A3** — Given `다크`를 고른 뒤 앱을 강제 종료했다면, When 앱을 다시 실행하면, Then 스플래시 직후부터 다크로 뜨고 라이트 프레임이 1프레임도 보이지 않는다.
- **US-39-A4** — Given `라이트`를 명시적으로 골랐다면, When OS 테마를 다크로 바꾸면, Then 앱은 라이트를 유지한다(명시 선택이 OS보다 우선한다).
- **US-39-A5** — Given `다크`를 고른 상태에서 로그아웃하고 다른 계정으로 로그인했다면, When 앱을 보면, Then 여전히 다크다(테마는 계정 데이터가 아니라 기기 취향이다).
- **US-39-A6** — Given 다크 테마라면, When 화면 상단·하단의 시스템 영역을 보면, Then 상태바 아이콘이 밝은색이고 내비게이션바 배경이 앱 배경과 같은 색이며, 화면 전환 사이에 흰 섬광이 보이지 않는다.
- **US-39-A7** — Given 문서 필드를 편집하는 중이라면, When 설정으로 가서 테마를 바꾸고 돌아오면, Then 입력하던 값이 그대로 남아 있다.

## EP-7. 상용 품질 (Phase 7)

### US-33. 지하철에서도 열린다
**지훈으로서** 네트워크가 없어도 저장한 명함을 보고 싶다, **이동 중 상대 연락처를 확인하기 위해.**
FR: FR-101, FR-102

- **US-33-A1** — Given 이전에 조회한 명함 목록이 있고 기기가 비행기 모드라면, When 보관함에 들어가면, Then 캐시된 목록과 이미지가 표시된다.
- **US-33-A2** — Given 오프라인 상태라면, When 화면 상단을 보면, Then `오프라인` 배너가 표시된다.
- **US-33-A3** — Given 오프라인 상태라면, When 저장·수정·삭제를 시도하면, Then 버튼이 비활성이고 사유가 안내된다.
- **US-33-A4** — Given 네트워크가 복구됐다면, When 앱이 이를 감지하면, Then 배너가 사라지고 진행 중이던 조회가 자동 재시도된다.
- **US-33-A5** — Given 일시적 네트워크 오류로 목록 조회가 실패했다면, When 자동 재시도가 동작하면, Then GET은 최대 2회 재시도되고 저장 요청은 자동 재시도되지 않는다.

### US-34. 손끝의 감각으로 확인한다
**서연으로서** 중요한 동작이 성공했는지 진동으로도 알고 싶다, **화면을 계속 보지 않아도 되기 위해.**
FR: FR-104, FR-105, FR-106

- **US-34-A1** — Given 셔터·저장 성공·삭제·새로고침·탭 전환 중 하나를 수행했다면, When 동작이 완료되면, Then 각각에 맞는 강도의 햅틱이 발생한다.
- **US-34-A2** — Given 설정에서 햅틱을 껐다면, When 같은 동작을 수행하면, Then 진동이 발생하지 않는다.
- **US-34-A3** — Given OS `reduce motion`이 켜져 있다면, When 화면을 전환하면, Then 애니메이션이 축소되거나 생략된다.
- **US-34-A4** — Given 리스트에서 세로 스크롤 중이라면, When 손가락이 약간 좌우로 흔들려도, Then 스와이프 삭제가 오작동하지 않는다.

### US-35. 눈으로 보지 않고도 쓴다
**시각 보조 기술 사용자로서** 스크린리더로 앱을 조작하고 싶다, **명함 정보를 독립적으로 확인하기 위해.**
FR: FR-107 / NFR-022, NFR-024

- **US-35-A1** — Given TalkBack이 켜져 있다면, When 화면을 훑으면, Then 아이콘 전용 버튼도 의미 있는 라벨을 읽어준다.
- **US-35-A2** — Given TalkBack 사용 중이라면, When 로그인 → 스캔 → 저장 → 검색 흐름을 수행하면, Then 화면을 보지 않고 완주 가능하다.
- **US-35-A3** — Given 흑백 스크린샷을 본다면, When 문서 유형·읽음 여부를 판별하면, Then 색 외의 단서(텍스트·아이콘)로 구분된다.
- **US-35-A4** — Given 화면에 진입했다면, When 포커스 순서를 따라가면, Then 시각적 순서와 논리적 순서가 일치한다.

### US-36. 오래 써도 느려지지 않는다
**지훈으로서** 30분 연속으로 명함을 스캔해도 앱이 버벅이지 않길 원한다, **행사 하루를 이 앱으로 버티기 위해.**
FR: FR-108, FR-109 / NFR-001, NFR-003, NFR-008, NFR-009

- **US-36-A1** — Given 저사양 기준기기라면, When 앱을 콜드스타트하면, Then 2.5초(P90) 내 첫 인터랙티브 프레임이 나온다.
- **US-36-A2** — Given 스캔→저장을 30회 반복했다면, When 메모리를 측정하면, Then baseline 대비 증가가 80MB 이하다.
- **US-36-A3** — Given 임의의 비동기 화면이라면, When 상태를 순회하면, Then 로딩·빈 상태·에러·재시도 4상태가 모두 구현되어 있다.
- **US-36-A4** — Given 4주간 사용 데이터라면, When 크래시프리 세션율을 계산하면, Then 99.5% 이상이다.

## EP-8. 릴리스 (Phase 8)

### US-37. 팀원이 설치해서 쓴다
**DEV로서** 서명된 APK를 팀에 배포하고 싶다, **실제 기기에서 검증받기 위해.**
FR: FR-113, FR-114, FR-116, FR-117, FR-118

- **US-37-A1** — Given 릴리스 빌드 프로필이라면, When 빌드를 실행하면, Then AAB가 아니라 설치 가능한 `.apk`가 산출된다.
- **US-37-A2** — Given 산출된 APK라면, When 서명을 검증하면, Then v2/v3 서명이 유효하다고 보고된다.
- **US-37-A3** — Given Android 8 / 12 / 14 기기 각 1대라면, When APK를 설치하고 핵심 루프를 수행하면, Then 3기종 모두 완주한다.
- **US-37-A4** — Given 배포 문서만 받은 팀원이라면, When 문서를 따라가면, Then 설치와 LAN IP 연결까지 스스로 완료한다.
- **US-37-A5** — Given keystore라면, When 저장소를 검사하면, Then keystore 파일과 비밀번호가 커밋되어 있지 않다.

### US-38. 가볍고 빠른 배포본
**DEV로서** APK 용량과 성능 예산을 지키고 싶다, **설치 이탈과 저사양 기기 문제를 줄이기 위해.**
FR: FR-115, FR-119, FR-120 / NFR-028

- **US-38-A1** — Given release APK라면, When 파일 크기를 측정하면, Then 80MB 이하다.
- **US-38-A2** — Given R8/ProGuard를 적용했다면, When 전 기능 회귀 테스트를 수행하면, Then 난독화로 인한 기능 저하가 0건이다.
- **US-38-A3** — Given 릴리스 후보라면, When QA 체크리스트를 수행하면, Then 100% pass이거나 미통과 항목마다 사유와 후속 계획이 기록되어 있다.
- **US-38-A4** — Given 새 릴리스를 낸다면, When 앱 정보 화면을 보면, Then 버전과 빌드번호가 이전 릴리스보다 증가해 있다.
