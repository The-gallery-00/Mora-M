## 판정과 확인 범위

현재는 내부 테스트용 구현과 AAB 빌드 이력까지 갖춰진 상태다. 공개 출시 준비 완료로 판정할 수 없다.
가장 먼저 해결할 문제는 GCP 결제 비활성화와 Cloud SQL 중지다.

- `git fetch origin` 후 로컬 `dev`와 `origin/dev`가 모두 `9b182be`임을 확인했다.
- 최신 커밋은 2026-08-19의 `feat: 검색·카메라·홈 일정·보관함 UX 개선 (#46)`이다.
- 앱, Spring, OCR 코드와 실제 GCP 서비스 설정을 읽고 비인증 HTTP 응답을 확인했다.
- 테스트 계정을 생성하거나 사용자 문서 및 이미지를 변경하지 않았다.
- Play Console과 각 소셜 제공자 관리 콘솔의 현재 상태는 이번에 확인하지 않았다.
- 코드 구현의 존재는 실제 단말에서의 성공을 의미하지 않는다. 아래의 재검증 항목을 별도로 통과해야 한다.

## 실제 배포 상태

| 항목 | 확인값 |
|---|---|
| GCP 프로젝트 | `mora-mobile` |
| 결제 | `billingEnabled: false` |
| Cloud SQL | `mora-mobile-db`, PostgreSQL 16, `SUSPENDED`, 사유 `BILLING_ISSUE` |
| DB 규모 | `db-f1-micro`, 단일 영역 `ZONAL` |
| DB 백업 설정 | 자동 백업 활성, 보관 개수 7. 실제 최근 백업 및 복구 성공은 미확인 |
| DB 삭제 보호 | 비활성 |
| Spring | `mora-mobile-spring-00021-hzt`, 1 CPU / 1 GiB, 최대 인스턴스 3 |
| OCR | `mora-mobile-ocr-00008-qgx`, 1 CPU / 2 GiB, 최대 인스턴스 3 |
| HTTP 실측 | Spring `/auth/me`: 500, OCR `/`: 500 |
| JWT | 운영 설정 `1209600000` ms = 14일 |
| 업로드 | OCR에 `GCS_BUCKET_NAME=mora-mobile-uploads` 및 `uploads` 접두사 설정 |
| GCS 삭제 보관 | soft delete 7일 설정 확인. 삭제 즉시 영구 소거되는 구조는 아님 |
| 비밀정보 | DB 비밀번호, JWT, 소셜 인증 정보는 Secret Manager 참조로 연결 |
| OpenAI | 운영 Spring의 `OPENAI_API_KEY`가 설정되지 않음 |

Cloud Run의 과거 `Ready=True`와 트래픽 100% 표시는 현재 서비스 정상 응답의 증거가 아니다.
DB 중지 사유와 결제 비활성은 확인했지만, 두 HTTP 500 각각의 세부 원인은 결제 복구 후 다시 확인해야 한다.

## 출시 전 필수 보완

### P0: 결제와 서비스 복구

운영자가 GCP 결제 화면에서 연결된 결제 계정의 결제 수단, 미납, 계정 정지 또는 크레딧 종료 여부를 확인한다.
확인된 것은 결제 문제라는 사실이며, 구체적인 결제 실패 원인은 아직 확인하지 않았다.
결제를 정상화한 뒤 DB `RUNNABLE`, Spring 비인증 `/auth/me`의 401, OCR `/health`의 실제 추론 성공을 확인한다.
DB 복구 후 사용자·문서 데이터와 백업 상태도 확인한다.

Google Cloud 문서상 결제 문제 해결 후 복구에 수 시간이 걸릴 수 있다.
Cloud SQL FAQ에는 `SUSPENDED`가 90일 지속된 인스턴스가 삭제된다고 안내되어 있으므로 복구를 우선한다.
현재 중지 시작일과 남은 기간은 확인하지 않았다.

근거: [Cloud SQL 진단](https://docs.cloud.google.com/sql/docs/postgres/diagnose-issues), [FAQ](https://docs.cloud.google.com/sql/docs/postgres/faq).

### P1: OCR와 이미지 접근 인증

`server/ocr/app.py`의 `GET /uploads/{image_name}`, `DELETE /uploads/{image_name}`에 인증·소유자 검증이 없다.
`server/ocr/routers/ocr.py`의 `/api/scan`, `/api/commit`도 인증을 요구하지 않는다.
파일명을 안다는 이유로 문서 원본에 접근하거나 삭제할 수 있어서는 안 된다.
인증된 Spring 경유 접근 또는 인증·소유자 검증과 서버 간 권한을 설계하고, 다른 사용자 접근 거부를 테스트한다.
앱의 이미지 로딩과 업로드 경로도 함께 수정해야 한다.

### P1: 4종 이미지 삭제 완성

`AuthService.deleteAccount`와 `UserDataService.deleteAllDocuments`는 명함 이미지에만 삭제 요청을 보낸다.
포스터·티켓·영수증의 개별 삭제는 DB 레코드만 지운다.
4종 모두의 이미지 참조를 추출해 개별 삭제·전체 삭제·탈퇴 시 정리하도록 구현한다.
스캔 취소·저장 실패로 남는 이미지도 수명주기 정리가 필요하다.
DB와 GCS가 함께 삭제되는지, 중간 실패와 재시도가 가능한지 테스트한다.

### P1: 소셜 로그인 보안과 실제 로그인

Google·Kakao 인증 요청에 요청자와 콜백을 연결해 검증하는 `state` 처리가 없다.
Naver는 임의 `state`를 생성하지만 서버에 저장한 값과 비교하지 않고 콜백 값의 존재만 검사한다.
일회성·만료·요청자 바인딩을 갖춘 상태 검증을 추가한다.
현재 앱 복귀 URL은 JWT와 사용자 정보를 쿼리에 싣는다. 일회용 교환 코드 방식으로 개선하는 것을 권장한다.
세 제공자 모두 실제 계정으로 로그인, 취소, 거절, 앱 종료 상태 복귀를 확인한다.
이전 Kakao 로그인 화면 접근 확인은 토큰 발급과 앱 복귀 성공의 증거가 아니다.

### P1: 미완성 기능 처리

- Google Calendar: `GoogleCalendarService.connectUrl`은 설정이 있어도 미구현 예외를 던진다. 월 응답의 `events`도 빈 목록으로 초기화되고 실제 Google API를 호출하지 않는다. 실제 연동을 구현하거나 출시 화면에서 제외한다.
- 챗봇: 앱은 `POST /api/chat`을 호출하지만 Spring 컨트롤러와 별도 LLM 서버 구현이 없다. 인증·소유 문서 검색·응답 생성을 구현하거나 진입점을 제외한다.
- 의미 검색: 운영 OpenAI 키 미설정으로 임베딩 생성이 생략된다. 일반 OCR 자체의 필수 키는 아니다. 의미 검색을 제공하려면 Secret Manager 연결, 기존 문서 재색인 및 검색 결과 검증이 필요하다.
- 영수증: 품목 단위 `items[]` 조립은 미완성이다. 상호·구매일·총액 중심 지원과 품목 인식을 구분해 안내하거나 품목 추출을 추가한다.
- 알림: 앱 내 알림과 기기 푸시를 구분한다. 기기 푸시를 출시 기능으로 약속하려면 추가 구현이 필요하다.

### P1: 사진 권한과 공개 정책

현재 `app.config.js`가 `READ_MEDIA_IMAGES`를 선언하고 `useScan.ts`가 앨범 권한을 선요청한다.
단일 문서 사진 선택에는 시스템 Photo Picker를 사용하도록 바꾸고 불필요한 광범위 사진 권한을 제거하는 것이 적절하다.
최종 AAB의 병합된 매니페스트와 실제 기기 권한 흐름도 검사한다.
근거: [Google Play 권한 정책](https://support.google.com/googleplay/android-developer/answer/16558241).

개인정보처리방침에는 이미지가 외부 사업자로 전송되지 않는다고 적혀 있지만 운영은 GCS를 사용한다.
문서 저장 위탁, 소셜 로그인, 실제 AI 전송 범위, 백업·soft delete·로그 보관 기간과 실제 동작을 맞춰야 한다.
`server/DATA_SAFETY.md`도 명함 중심 항목과 현재 기능 차이를 갱신해야 한다.
외부 개인정보처리방침 URL과 계정 삭제 요청 URL은 Play Console에서 실제 등록·공개 접근 여부를 확인한다.
앱 재설치를 요구하지 않고 외부에서 삭제 요청할 수 있어야 한다.
근거: [Google Play 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111).

### P2: 배포·품질·운영 정리

- Spring의 현재 리비전 준비 시각은 2026-08-18이며 최신 dev의 08-19 알림 DTO 수정에는 `sourceType`·`sourceId` 추가가 있다. 배포된 바이너리의 해당 필드 반영을 확인하고 결제 복구·코드 수정 후 최신 서버를 재배포한다.
- DB 백업 실제 성공, 복원 절차, 삭제 보호, 서비스 장애 알림·예산 알림·동시 업로드 부하를 점검한다. 현재 작은 DB와 인스턴스 제한이 대규모 사용자 수를 감당한다는 보장은 없다.
- Cloud Run에서 인스턴스가 없거나 여러 개일 때 일일 예약 알림 생성이 누락·중복되지 않는지 확인한다. 현재 요청 시 알림 보충 생성도 구현되어 있다.
- 최신 SDK 패치·의존성 취약점을 점검한다. 현재 의존성 보안 검사는 이번 범위에서 실행하지 않았다.
- TypeScript는 통과했지만 린트 실패가 남아 있다. Reanimated shared value와 React Compiler 규칙 간 오탐 여부를 구분하고 실제 훅 문제를 수정한다. 무조건 규칙 전체를 끄는 방식으로 해결하지 않는다.
- README와 위키에 Phase 0, LAN 전제, 예전 패키지명, 다크모드 범위 등 현재 코드와 다른 내용이 남아 있다. 현재 상태의 근거로 그대로 쓰지 않는다.

## 빌드·출시 기록과 추가 확인

- 로컬에 `mora-mobile-production-20260820.aab`가 있으며 약 96 MB다.
- 이전 작업 기록상 이 파일은 최신 `9b182be` 기준이며 EAS Android versionCode는 8이었다. 이번에는 원격 버전이나 AAB 내부를 다시 추출·검증하지 않았다.
- 앱 설정의 실제 버전 문자열은 `0.1.0`이다. 이전 출시명 `v1.0.8`은 실제 versionName과 다르므로 이후에는 실제 버전과 맞춘다.
- Play Console의 실제 배포 트랙, 업로드된 versionCode, 테스터 수·참여 기간·프로덕션 접근 승인 상태는 미확인이다.
- 해당되는 신규 개인 개발자 계정은 비공개 테스트 12명 이상이 연속 14일 참여한 뒤 프로덕션 접근을 신청해야 한다. 내부 테스트만으로 대체하지 않는다. [공식 안내](https://support.google.com/googleplay/android-developer/answer/14151465).
- 제출 시점의 target API 요건과 네이티브 라이브러리의 16 KB 페이지 크기 호환성은 최종 AAB 및 Play Console로 확인한다. 이번에는 합격 판정하지 않았다. [Target API](https://support.google.com/googleplay/android-developer/answer/11926878), [16 KB 지원](https://developer.android.com/guide/practices/page-sizes).
