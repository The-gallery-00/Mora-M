# Mobile UX Guide

웹 MORA를 상업앱 수준 네이티브 경험으로 바꾸기 위한 **규범 문서** — 변환 규칙·백버튼·키보드·로딩 위계·문구·모션·햅틱·권한·접근성·**테마(라이트/다크)**의 강제 기준.

관련: [[Design Tokens]] · [[Navigation Map]] · [[Component Library]] · [[Screen Specs]] · [[QA Checklist]] · [[Offline and State]] · [[ADR-004 Styling]]

## 0. 이 문서의 지위

1. 이 문서의 규칙은 **기본값이 아니라 요구사항**이다. 어기려면 [[Screen Specs]]의 해당 화면에 예외 사유를 적어야 한다.
2. 규칙에는 `UX-##`(변환·인터랙션), `MOT-##`(모션), `HAP-##`(햅틱), `A11Y-##`(접근성), `CP-##`(문구) ID를 붙인다. 리뷰·QA는 이 ID로 지적한다.
3. **웹 원본을 "그대로 옮기는 것"은 실패다.** 원본 대시보드는 `minWidth: 1200`을 하드코딩했고(`app/dashboard/layout.tsx:368`), 인터랙션의 절반이 hover·키보드 전제다. 아래 표는 그 전부를 대체 관용구로 치환한다.
4. **원본 한국어 카피는 자산이다.** §7 문구 표의 "원본" 열에 있는 문자열은 실제 코드에서 추출한 것이며, 임의 창작 금지 — 다듬을 때도 표에 최종안을 등록하고 그 문자열만 쓴다.

## 1. 5대 원칙

| # | 원칙 | 구체 기준 |
|---|---|---|
| 1 | **한 손으로 끝난다** | 주요 액션(스캔·저장·검색·삭제 확인)은 화면 하단 1/3에 배치. 상단에는 파괴적 버튼을 두지 않는다 |
| 2 | **기다림을 보여주지 않는다** | 낙관적 업데이트 > 스켈레톤 > 스피너 (§6). 200ms 이상 걸리는 모든 것에 위계를 적용 |
| 3 | **되돌릴 수 있다** | 삭제는 스낵바 `실행 취소`(5초) 우선, 서버 확정은 그 후. 되돌릴 수 없는 것만 확인 다이얼로그 |

## 3. 세이프에어리어 / 노치 / 제스처 바

**규칙**
1. **`SafeAreaProvider`를 루트에 1회만** 마운트. 화면에서는 `useSafeAreaInsets()`를 쓰고 `SafeAreaView`는 쓰지 않는다(중첩 시 여백이 두 번 먹는다).
2. **상단 inset**: 커스텀 헤더를 쓰는 화면만 `paddingTop: insets.top`. expo-router 네이티브 헤더를 쓰면 자동 처리되므로 추가 금지.
3. **하단 inset**: 탭바 높이 = `layout.tabBarHeight(56) + insets.bottom`. 스크롤 콘텐츠는 `contentContainerStyle.paddingBottom = tabBarHeight + insets.bottom + 16`.
4. **바텀시트**: `bottomInset`을 시트 라이브러리에 넘기지 말고 시트 내부 마지막 요소에 `paddingBottom: insets.bottom + 16`. 제스처 바와 CTA 버튼이 겹치면 안 된다.
5. **FAB**: `bottom = tabBarHeight + insets.bottom + 16`.
6. **전체화면(카메라)**: 프리뷰는 inset 무시하고 화면 전체를 채우되, **컨트롤(셔터·닫기·플래시)은 반드시 inset 안쪽**. 상단 닫기 = `insets.top + 8`, 하단 셔터 = `insets.bottom + 24`.
7. **가로 inset**: 폴더블/노치 가로모드 대비 `paddingHorizontal = max(16, insets.left/right)`.
8. **Android 제스처 내비게이션**: 화면 좌우 가장자리 24dp 이내에 수평 스와이프 제스처(스와이프-삭제 등)를 배치하지 않는다. 리스트 스와이프는 좌측 가장자리 24dp를 제외한 영역에서만 시작하도록 `activeOffsetX` 설정.
9. **키보드와 inset 동시 적용 금지**: 키보드가 올라오면 `insets.bottom`은 0으로 취급한다(`KeyboardAvoidingView`가 이미 처리).
10. 화면 회전: **결정 — v1은 세로 고정**(`"orientation": "portrait"`). 예외: 문서 이미지 뷰어(`/image/[id]`)만 가로 허용. 이유: 원본 화면 전부가 세로 스크롤 전제이고, 가로 레이아웃을 12화면 분량으로 검증할 여력이 없다.

## 4. 하드웨어 뒤로가기 정책 (Android)

전역 원칙: **백은 "취소"가 아니라 "이전 상태로"**. 데이터를 잃는 백은 반드시 확인을 받는다.

| 화면 / 상태 | 백 동작 | 확인 필요 | 문구 |
|---|---|---|---|
| 홈 탭 (루트) | **앱 종료 확인** — 2초 내 두 번 누르면 종료 | 토스트 | `한 번 더 누르면 종료됩니다` |
| 그 외 탭 루트(보관함/검색/설정) | **홈 탭으로 이동** (종료 아님) | 없음 | — |
| 스택 하위 화면 (문서 상세 등) | pop | 없음 | — |
| 바텀시트 / 액션시트 | 시트 닫기 (화면 유지) | 없음 | — |
| 모달 (챗봇, 알림, 이미지 뷰어) | 모달 닫기 | 없음 | — |
| 스캔 카메라 (`/scan`) | 촬영본 없으면 즉시 닫기 / 있으면 확인 | Alert | `촬영한 사진을 버릴까요?` · `버리기` / `계속` |
| 스캔 결과 확인·편집 (`/scan/review`, SCR-12) | dirty면 확인, 아니면 pop | Alert | `저장하지 않고 나갈까요?` · `나가기` / `계속 편집` |
| 문서 상세 **편집 모드** | 편집 취소(읽기 모드 복귀), 화면 유지 | dirty면 Alert | 동일 |
| 로그인 / 회원가입 | 랜딩(welcome)으로 pop | 없음 | — |
| 랜딩(welcome) | 앱 종료 | 없음 | — |
| OAuth 웹세션 | 세션 취소 → 로그인 화면 유지, 토스트 | 없음 | `로그인을 취소했어요` |
| 업로드/저장 진행 중 | **백 차단** (진행률 표시 중) | 없음 | 상단 배너 `저장 중이에요. 잠시만요` |
| 온보딩 슬라이드 | 이전 슬라이드, 첫 장에서는 종료 | 없음 | — |

**구현**
- 화면 단위 처리는 `useFocusEffect` + `BackHandler.addEventListener('hardwareBackPress', ...)` 조합. 반드시 cleanup에서 `remove()`.
- dirty 가드는 `usePreventRemove`(react-navigation 7) 또는 `beforeRemove` 리스너로 처리하고, **iOS 스와이프 백도 같은 가드를 타야 한다**(`gestureEnabled: false` + 커스텀 헤더 백 버튼으로 통일).
- 이중 백 종료는 홈 탭에서만. 다른 탭에서 종료되면 사용자가 데이터를 잃었다고 느낀다.

## 5. 키보드 처리

1. **`KeyboardAvoidingView`는 화면 루트에 1개.** `behavior={Platform.OS === 'ios' ? 'padding' : 'height'}`, Android는 `android:windowSoftInputMode="adjustResize"`를 `app.json`에 명시. 시트 안에서는 `BottomSheetTextInput` + `keyboardBehavior="interactive"`.
2. **폼 스크롤은 `KeyboardAwareScrollView`가 아니라 `ScrollView` + `keyboardShouldPersistTaps="handled"`.** 입력 중 버튼을 한 번에 누를 수 있어야 한다(두 번 탭 방지).
3. **포커스 자동 스크롤**: 포커스된 입력의 하단이 키보드 위 16dp 이상 보이도록 스크롤. 마지막 필드는 `contentContainerStyle.paddingBottom`으로 여유 확보.
4. **returnKeyType 체인** — 원본 폼 그대로:

| 화면 | 필드 순서 | returnKeyType | submit 동작 |
|---|---|---|---|
| 로그인 | 이메일 → 비밀번호 | `next` → `done` | 비밀번호에서 `done` = 로그인 제출 |
| 회원가입 | 이메일 → 비밀번호 | `next` → `done` | `done` = 가입 제출 |
| 비밀번호 변경 | 현재 → 새 → 확인 | `next` → `next` → `done` | `done` = 변경 제출 |
| 닉네임 변경 | 닉네임 | `done` | `done` = 저장 |
| 검색 | 질의 | `search` | `search` = 검색 실행 |
| 챗봇 입력 | 메시지 | `send` | `send` = 전송(문서 타입 미선택이면 비활성) |
| 스캔 필드 편집 | OCR 필드 n개 | 마지막 외 `next`, 마지막 `done` | `done` = 키보드 닫기(저장 아님 — 오저장 방지) |

5. **키보드 타입/자동완성**: 이메일 `keyboardType="email-address" autoCapitalize="none" autoComplete="email" textContentType="emailAddress"`, 비밀번호 `secureTextEntry autoComplete="password" textContentType="password"`(가입 시 `newPassword`), 전화 `keyboardType="phone-pad"`, 금액 `keyboardType="numeric"`, 날짜 필드는 **키보드 대신 날짜 피커 시트**.
6. **폼 제출 흐름**: 제출 시 (1) 키보드 닫기 → (2) 버튼을 로딩 상태로(라벨 유지 + 인라인 스피너) → (3) 성공 시 화면 전환, 실패 시 키보드 다시 열지 않고 에러를 필드 하단에 표시.
7. **입력 폰트 16 이상**(`typography.input`). 16 미만이면 iOS가 포커스 시 화면을 확대한다.
8. **비밀번호 표시 토글**은 오른쪽 내부 아이콘(`Eye`/`EyeOff`, 20dp, hitSlop `md`). `accessibilityLabel`은 원본 그대로 `비밀번호 보기` / `비밀번호 숨기기`.
9. **키보드 위 액세서리 바 금지**(iOS 전용이라 플랫폼 불일치). 대신 제출 버튼을 폼 하단에 고정.

## 6. 로딩 위계

> 원칙: **낙관적 업데이트 > 스켈레톤 > 스피너.** 아래에서 위 단계를 선택할 수 없을 때만 내려간다.

| 단계 | 언제 | 구현 | 적용 사례 |
|---|---|---|---|
| **0. 즉시(캐시)** | 이미 받아온 데이터가 있을 때 | TanStack Query `staleTime` + 캐시 우선 렌더, 백그라운드 refetch | 보관함 재진입, 홈 재진입, 문서 상세 |
| **1. 낙관적 업데이트** | 결과를 예측할 수 있고 롤백이 가능할 때 | 로컬 상태 즉시 반영 → 실패 시 롤백 + 토스트 | 삭제, 그룹 이동, 필드 수정 저장, 알림 읽음 처리, 문서 타입 변경 |
| **2. 스켈레톤** | 화면/리스트의 **최초** 로드, 레이아웃을 미리 알 때 | 실제 카드와 같은 형태의 회색 블록 + shimmer 1200ms | 보관함 목록, 검색 결과, 홈 마감 카드, 문서 상세 |
| **3. 인라인 진행률** | 시간이 걸리고 진행도를 알 수 있을 때 | 결정적 프로그레스 바 + 단계 라벨 | 이미지 업로드(바이트 진행률), OCR 스캔(단계 4개) |
| **4. 버튼 인라인 스피너** | 사용자가 방금 누른 단일 액션 | 버튼 라벨 유지 + 좌측 12dp 스피너 + `disabled` | 로그인, 저장, 그룹 추가 |
| **5. 전체 스피너** | 위 어느 것도 불가능할 때만 | 중앙 `ActivityIndicator` | 앱 부팅 세션 복원(스플래시로 대체 권장) |

**보조 규칙**
- **200ms 룰**: 200ms 안에 끝나면 로딩 UI를 아예 띄우지 않는다(깜빡임 방지). 스켈레톤은 한 번 뜨면 **최소 400ms 유지**.
- **10초 룰**: 10초를 넘기면 `조금 오래 걸리고 있어요`(CP-31) 보조 문구 + `취소` 버튼 노출. OCR 스캔은 서버 평균 2초지만 LAN 상황에 따라 길어질 수 있다.
- 원본의 텍스트 로딩(`로딩 중...`, `불러오는 중...`, `검색 중...`)은 전부 **스켈레톤으로 대체**하고 문자열은 폐기한다(§7 참조).
- pull-to-refresh는 스켈레톤을 띄우지 않는다(기존 콘텐츠 유지 + 상단 인디케이터).

### 7-3. 문체 규칙

**결정: 사용자에게 말하는 문구는 `-어요/-예요` 체로 통일한다.** 단 두 가지 예외:
1. **파괴적 확인·법적 고지**는 `-습니다` 체 유지 (`이 작업은 되돌릴 수 없습니다.`) — 무게감이 필요하다.
2. **원본 유지 표시된 문구**는 그대로 둔다 — 이미 검증된 카피이고 바꿀 이유가 없다.

추가 규칙:
- 서버가 준 `res.error` 문자열을 **그대로 노출하지 않는다.** 상태코드/에러코드를 위 표의 CP-## 로 매핑해서 보여준다. 이유: 서버 문구가 영문(`Login required`, `Too many requests, try again later`)이거나 한글 인코딩이 깨지는 사례가 실재한다(04-api.md 함정 3).
- 느낌표·이모지 금지. `!` 는 축하 토스트에도 쓰지 않는다.
- 사용자를 탓하지 않는다: "잘못 입력하셨습니다" ❌ → "다시 확인해 주세요" ✅.

3. **duration 500ms 초과 금지.** 예외: 스켈레톤 shimmer(loop), 진행률.

## 10. 권한 요청 UX

**3단 구조 강제: pre-permission 설명 → OS 다이얼로그 → 거부 시 설정 유도.** OS 다이얼로그를 맨 처음 띄우는 코드는 리뷰에서 반려한다(iOS는 거부 후 재요청 자체가 불가능하다).

| 권한 | 요청 시점 | pre-permission 화면 | 거부 시 |
|---|---|---|---|
| 카메라 | **스캔 탭 첫 진입 시** (앱 첫 실행 아님) | 제목 `카메라로 문서를 찍어 주세요` / 본문 `명함·티켓·포스터·영수증을 촬영하면 MORA가 내용을 읽어 정리합니다. 사진은 문서 인식에만 사용돼요.` / `카메라 허용` · `앨범에서 고르기` | 앨범 경로로 폴백 + 상단 `설정에서 카메라 켜기` 버튼 |
| 사진(앨범) | 사용자가 `앨범에서 고르기`를 탭했을 때 | 제목 `앨범에서 사진을 불러올게요` / 본문 `선택한 사진만 읽습니다. 앨범 전체를 열어보지 않아요.` / `앨범 열기` | 시트: `설정에서 사진 접근을 허용하면 바로 불러올 수 있어요` + `설정 열기` |
| 알림 | **첫 문서 저장 성공 직후** (가치 증명 후) | 제목 `마감이 다가오면 알려드릴게요` / 본문 `포스터 마감일과 티켓 출발일이 가까워지면 알림을 보냅니다. 하루 한 번만 확인해요.` / `알림 받기` · `나중에` | 조용히 종료. 설정 > 알림에서 언제든 켤 수 있음 |

**세부**
1. iOS 14+ 사진 "제한된 접근(Limited)" 대응: `expo-image-picker`는 제한 모드에서도 동작한다. 제한 상태에서 원하는 사진이 없으면 `사진 더 선택하기`(`presentLimitedLibraryPickerAsync`) 안내.
2. Android 13+(API 33)는 `READ_MEDIA_IMAGES`, 그 이하는 `READ_EXTERNAL_STORAGE`. Expo 플러그인이 처리하지만 `app.json` 권한 목록에서 불필요한 권한(오디오/비디오)을 **명시적으로 제거**한다.
3. **`Linking.openSettings()`는 항상 시트/Alert를 거쳐서** 호출한다. 버튼 하나로 앱 밖으로 튕기면 안 된다.
4. 앱 재진입 시 권한 상태를 다시 확인(`useFocusEffect`)해 배너를 자동으로 없앤다.
5. **iOS `Info.plist` 문구(한국어)** — `app.json` `ios.infoPlist`:
   - `NSCameraUsageDescription`: `문서를 촬영해 자동으로 정리하기 위해 카메라를 사용합니다.`
   - `NSPhotoLibraryUsageDescription`: `앨범에서 문서 사진을 불러오기 위해 사진 접근이 필요합니다.`
   - `NSPhotoLibraryAddUsageDescription`: `문서 이미지를 앨범에 저장하기 위해 사용합니다.`
6. **푸시 사실관계 (v1 범위 결정)**: 서버에는 FCM/APNs 디바이스 토큰을 저장할 컬럼·엔티티가 **없다**. 알림은 매일 09:00 KST 배치가 DB row를 만드는 방식뿐이다(05-domain.md §6). **결정: v1은 원격 푸시를 구현하지 않고 (a) 앱 포그라운드 진입 시 `GET /api/notifications/unread-count` 폴링 + (b) 저장 시점에 로컬 알림(`expo-notifications` 스케줄) 등록으로 대체한다.** 알림 권한 문구도 이 범위에 맞춰 "하루 한 번만 확인해요"로 정직하게 쓴다. 원격 푸시는 서버 변경이 필요하므로 [[Risks]]에 등록.

## 11. 접근성 체크리스트 (A11Y)

**웹 원본은 `aria-*`가 잘 붙어 있다. 이 자산을 그대로 이전한다** — `role="listbox|option|switch|img"`, `aria-expanded/selected/checked/label/hidden`.

| ID | 항목 | 기준 | 매핑 |
|---|---|---|---|
| A11Y-01 | 모든 터치 요소에 이름 | `accessibilityLabel` 필수 | `aria-label` → `accessibilityLabel` |
| A11Y-02 | 역할 지정 | 버튼/링크/이미지/헤더/탭 | `role` → `accessibilityRole="button|link|image|header|tab|switch"` |
| A11Y-03 | 상태 전달 | 선택/비활성/체크/펼침 | `aria-selected|checked|expanded|disabled` → `accessibilityState={{selected,checked,expanded,disabled}}` |
| A11Y-04 | 장식 요소 숨김 | 아이콘·구분선·배경 이미지 | `aria-hidden` → `accessibilityElementsHidden`(iOS) + `importantForAccessibility="no-hide-descendants"`(Android) |
| A11Y-05 | 그룹 묶기 | 리스트 카드는 1개 항목으로 읽히게 | `accessible={true}` on 카드 루트, 내부 자식은 label 조합 |
| A11Y-06 | 터치 타겟 | 최소 44dp (§[[Design Tokens]] §11) | `hitSlop` |
| A11Y-07 | 색 대비 | 본문 4.5:1, 큰 글씨/아이콘 3:1 | 대비 미달 토큰(`#999`,`#94A3B8`)은 정보 전달 금지 |
| A11Y-08 | 색만으로 정보 전달 금지 | 문서 유형·수입/지출·D-day | 색 + **라벨 텍스트** 병기 (원본이 이미 배지에 텍스트를 넣고 있음) |
| A11Y-09 | 동적 텍스트 크기 | `allowFontScaling` 기본 true, 상한 1.3 | 배지·탭 라벨만 `maxFontSizeMultiplier={1.2}` |
| A11Y-10 | 모션 감소 | §8 전역 규칙 1 | `useReducedMotion()` |
| A11Y-11 | 스크린리더 알림 | 저장/삭제/에러 발생 시 | `AccessibilityInfo.announceForAccessibility(문구)` — 토스트는 시각 전용이라 반드시 병행 |
| A11Y-12 | 포커스 순서 | 화면 진입 시 헤더 제목부터 | 모달 열릴 때 `accessibilityViewIsModal={true}`(iOS)로 배경 차단 |
| A11Y-13 | 이미지 대체 텍스트 | 문서 썸네일 | `${유형} 이미지, ${제목}` 형식. 원본 `alt={displayTitle}` 계승 |
| A11Y-14 | 폼 오류 연결 | 필드-에러 연결 | `accessibilityLabel`에 에러 문구를 합쳐 읽히게 (`이메일, 오류: ...`) |
| A11Y-15 | 라벨 언어 | 한국어 | TalkBack/VoiceOver가 영문 식별자를 읽지 않도록 라벨은 전부 한국어 |

**검증 방법 (QA 항목)**: 실기기에서 TalkBack(Android) / VoiceOver(iOS)를 켜고 **핵심 3흐름을 눈 감고 완주** — (1) 로그인, (2) 스캔→저장, (3) 보관함에서 문서 삭제. 완주 불가 지점은 릴리스 블로커.

## 13. 안티패턴 (하면 반려)

1. 웹의 hover 스타일을 그대로 옮겨 놓고 press 상태를 만들지 않는 것.
2. `Alert.alert`로 성공을 알리는 것(성공은 토스트).
3. 로딩 스피너를 화면 전체에 띄우는 것(스켈레톤으로 대체 가능한데도).
4. 리스트 항목에 삭제 버튼을 상시 노출하는 것.
5. 서버 에러 문자열을 그대로 사용자에게 보여주는 것.
6. 화면마다 다른 간격/폰트를 쓰는 것(반드시 `theme` 토큰).
7. 키보드가 CTA 버튼을 가리는 것.
8. 백 버튼으로 입력한 내용이 조용히 사라지는 것.
9. 권한 다이얼로그를 앱 첫 실행에 몰아서 띄우는 것.
10. 무한 스크롤에 끝 표시가 없는 것(`더 이상 없어요` 또는 여백으로 종료를 알릴 것).
11. 다크에서 문서 이미지에 밝기·대비 필터를 걸어 스캔 원본을 어둡게 만드는 것(§14-3).
12. `dark:` 클래스로 색을 분기해 컴포넌트에 HEX를 되돌리는 것([[ADR-004 Styling]] §5-5).
13. 테마 전환을 위해 화면을 리마운트해 스크롤 위치·입력 중 텍스트를 날리는 것(UX-27).
14. "다크는 눈이 편해야 한다"며 §14-4 목록의 요소 대비를 낮추는 것.

## 14. 테마 (라이트 / 다크) UX 규범

**전제** — 다크모드는 v1 필수 기능이다([[ADR-004 Styling]] §4). 색 값의 정본은 [[Design Tokens]] §10, 배선 코드는 §13. 이 절은 **행동 규범**만 정한다. 테마는 3택(`시스템 따름` 기본값 / `라이트` / `다크`)이며 변경 지점은 설정 화면(SCR-25) 세그먼트 하나다.

### 14-1. 전환 규칙

| ID | 규칙 | 필수 세부 |
|---|---|---|
| **UX-25** | **시스템 테마 변경을 즉시 반영** | `시스템 따름`일 때 OS 테마가 바뀌면(제어센터 토글, 자동 야간 모드, 시간대 스케줄) **화면 재진입 없이 즉시** 반영한다. 앱이 백그라운드였다면 복귀 **첫 프레임에 이미 적용된 상태**여야 한다 — 복귀 후 깜빡이며 바뀌면 앱이 깨진 것처럼 보인다. 명시 선택(`라이트`/`다크`)은 OS 변경에 **흔들리지 않는다** |
| **UX-26** | **전환 애니메이션은 crossfade 200ms 1회뿐** | MOT-21. 화면 스냅샷 1장을 덮고 opacity로 지운다. 색을 개별 보간하지 않고, 어떤 요소도 이동·확대하지 않는다. 이유: 색 토큰 40여 개를 동시에 보간하면 저사양 기기에서 프레임이 무너지고, 중간 프레임의 색은 어느 테마에도 없는 값이라 대비 검증 대상이 아니다. `Reduce Motion`이면 즉시 교체 |
| **UX-27** | **전환이 상태를 건드리지 않는다** | 스크롤 위치, 열린 바텀시트, 입력 중 텍스트와 커서, 키보드 표시 여부, 진행 중 업로드 진행률이 **전부 유지**된다. 테마를 `key` prop에 넣어 리마운트로 처리하는 구현은 반려(§13 안티패턴 13) |
| **UX-28** | **설정에서 즉시 미리보기, 확인 버튼 없음** | 세그먼트 탭 → 즉시 적용 + HAP-01 `selectionAsync()`. 하단 힌트로 현재 상태를 말한다: `시스템 설정을 따릅니다.` / `현재 라이트 모드` / `현재 다크 모드`. 되돌리기는 세그먼트를 다시 탭하는 것이므로 실행 취소 스낵바를 붙이지 않는다(원칙 3의 예외 — 되돌림 비용이 탭 1회다) |
| **UX-29** | **테마는 로그아웃·계정 전환에도 유지** | `theme.mode`는 계정 데이터가 아니라 기기 취향이다. 로그아웃 정리 대상에서 제외한다 ([[Offline and State]] §1-4) |
| **UX-30** | **테마를 이유로 화면을 분기하지 않는다** | "다크 전용 레이아웃"을 만들지 않는다. 달라지는 것은 색·표면 밝기·에셋 3가지뿐이며, 간격·크기·계층 구조는 두 테마가 동일하다. 예외는 §14-3의 이미지 컨테이너 하나뿐이고, 그 예외는 [[Screen Specs]] SCR-12에 명시한다 |

### 14-2. 모션

MOT-21(테마 전환) · MOT-22(다크 스켈레톤 shimmer) — 수치는 §8 표가 정본이다. 여기서 추가로 강제하는 것:

1. 전환 crossfade 중에는 **입력을 막지 않는다.** 200ms 동안 터치가 죽으면 세그먼트 연속 탭이 씹힌다. 스냅샷 오버레이에 `pointerEvents="none"`.
2. 전환과 다른 애니메이션을 **겹치지 않는다**(§8 전역 규칙 4). 시트가 열리는 중에 테마가 바뀌면 시트 애니메이션을 끝내고 crossfade를 시작한다.
3. StatusBar / NavigationBar 색은 crossfade와 **동기로** 바꾼다. 시스템 바만 먼저 튀면 전환이 두 번 일어난 것처럼 보인다.

### 14-3. 다크에서의 이미지 처리 (눈부심 대응)

이 앱은 **흰 종이 문서 이미지**가 화면의 큰 면적을 차지한다. 다크 UI 위의 흰 이미지는 대비 충격이 가장 큰 조합이므로 규칙을 못박는다.

| 상황 | 규칙 | 이유 |
|---|---|---|
| 원칙 | **이미지 픽셀에 밝기·대비·틴트 필터를 걸지 않는다.** 눈부심은 **컨테이너**로 해결한다 | 이미지를 어둡게 하면 명함 작은 글씨·영수증 금액 판독성이 떨어진다. 사용자는 이 이미지를 **읽으려고** 저장했다 |
| 리스트·그리드 썸네일 | `surface.alt` 배경 + `border.subtle` 1px + `radius.card`, 이미지 사방 **4dp 매트** | 흰 면이 다크 배경에 직접 닿는 경계를 중간 휘도로 완충한다 |
| 문서 상세 이미지 | 컨테이너 `surface.alt` 프레임 + `contentFit="contain"`, 화면 배경 `bg.sunken` | 프레임이 이미지 경계를 명시해 "이미지가 어디까지인지"를 보여준다 |
| 전체화면 이미지 뷰어 | 배경 `bg.sunken`, 컨트롤 바 `overlay.image` | 이미지 판단이 목적인 화면이므로 이미지는 그대로 두고 주변만 어둡게 한다 |
| **스캔 리뷰(SCR-12)** | 다크에서도 **이미지 영역 컨테이너만 라이트 표면**(`#F8FAFC`)을 유지한다. bbox 오버레이 선은 다크 `action` 값 | 화면 절반이 흰 문서다. 이 컨테이너까지 다크로 만들면 눈부심이 최대가 된다. 테마 전환으로 사라지지 않는 문제라 **국소 예외**로 처리한다(UX-30의 유일한 예외) |
| 이미지 로딩 플레이스홀더 | 단색 `surface.alt`. 흰색 플레이스홀더 금지 | 로드 순간 흰 사각형이 번쩍인다 |
| 이미지 실패 폴백 | `surface.alt` + `text.muted` 아이콘 + `이미지가 없습니다`(CP-16) | UX-23과 동일 구조, 토큰만 교체 |
| 로그인 일러스트 `illust.png` | **다크에서 렌더하지 않는다** | 라이트 전제로 흰 배경이 합성된 에셋이다. 다크 버전을 새로 그리는 비용은 v1 밖이며, UX-24가 이미 "키보드 등장 시 숨김"을 규정하므로 숨김 경로가 존재한다 |
| OS 색 반전 접근성 기능 | 문서 이미지에 `accessibilityIgnoresInvertColors` 유지 | 다크모드와 색 반전은 **다른 기능**이다. 반전이 켜지면 스캔 문서가 음화가 되어 판독 불가가 된다 |

### 14-4. 다크에서 대비를 낮추면 안 되는 요소 (하드 리스트)

"다크는 눈이 편해야 한다"는 이유로 톤을 죽이는 실수가 가장 흔하다. 아래 요소는 **다크에서도 라이트와 같은 대비 기준을 지킨다.** 값은 [[Design Tokens]] §10-3/§10-4에서 이미 확보되어 있으므로, 화면 단계에서 opacity를 곱해 깎지 말라는 규칙이다.

| 요소 | 최소 기준 | 낮추면 생기는 일 |
|---|---|---|
| 본문·필드 값 텍스트 | 4.5:1 | 저장한 정보를 못 읽는다 |
| 파괴적 액션 라벨·아이콘 (삭제·탈퇴·전체 삭제) | 4.5:1 + **색 외 라벨 텍스트 병기** | 오조작 비용이 가장 큰 액션이다 (A11Y-08) |
| 폼 검증 에러 문구 / 에러 필드 보더 | 텍스트 4.5:1 · 보더 3:1 | 에러를 못 보면 폼이 영구히 막힌다 |
| 입력 필드 외곽선 · 포커스 링 | 3:1 (`border.strong`, WCAG 1.4.11) | 입력 가능 영역을 못 찾는다 |
| 선택·활성 상태 (활성 탭, 선택 칩, 캘린더 선택일, 세그먼트 인디케이터) | 3:1 + 색 외 단서(굵기·아이콘 채움) | 지금 어디에 있는지 모른다 |
| 문서 유형 배지 | 4.5:1 (§10-4) | 유형 오인 → 잘못된 유형으로 저장 |
| D-day · 마감 임박 강조 | 4.5:1 | 마감 알림이 이 앱의 핵심 가치다 |
| OCR bbox 오버레이 선·칩 | 이미지 위 3:1 | 흰 종이 위 밝은 선은 보이지 않는다. 다크에서 선을 더 밝히려는 유혹을 특히 경계 |
| 오프라인 배너 (OFF-02) | 4.5:1 | 상태를 오인해 저장 실패 이유를 이해하지 못한다 |
| 스낵바 `실행 취소` 액션 라벨 | 4.5:1 | 5초 안에 찾아 눌러야 한다 |
| 토스트 텍스트 | 4.5:1 | |
| 진행률 바 채움 vs 트랙 | 3:1 | 진행 여부 자체가 안 보인다 |
| 수입/지출 금액 부호 색 | 4.5:1 + 부호 문자 병기 | 성공색은 양 테마에서 텍스트 대비가 약하다 — 라이트는 `success.text #166534`를 쓴다([[Design Tokens]] §10-3) |

**반대로 다크에서 대비를 낮춰도 되는 것** (권장): 장식 구분선(`border.subtle`), 비활성 라벨·플레이스홀더(`text.disabled` — 양 테마 모두 AA 미달이 의도다), 스켈레톤, 빈 상태 일러스트 대체 아이콘, 카드 프레임.

### 14-5. 접근성 (테마 관련 추가)

| ID | 항목 | 기준 |
|---|---|---|
| **A11Y-16** | 테마 세그먼트 스크린리더 | 각 칸은 `accessibilityRole="button"` + `accessibilityState={{selected}}`, 그룹 라벨 `테마`. 변경 직후 `AccessibilityInfo.announceForAccessibility('다크 모드로 바꿨어요' / '라이트 모드로 바꿨어요' / '시스템 설정을 따릅니다')` — 시각 변화만으로는 전달되지 않는다 (A11Y-11과 동일 원칙) |

| **A11Y-18** | 두 테마 모두 검수 대상 | A11Y-07(색 대비) 검증은 **라이트/다크 각각** 수행한다. TalkBack/VoiceOver 3흐름 완주(§11)는 테마 1개에서만 해도 되지만, 대비 판정은 두 벌이다 — 케이스는 [[QA Checklist]] |
