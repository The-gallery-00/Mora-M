# ML 필드 추출기 도입 판단 (2026-08)

**결론: 도입하지 않는다.** 규칙 파서를 유지하고 개선한다.

웹 저장소에 `eval/models/fe_poster_v8` 이 있다 — klue/bert 기반 필드 분류기,
`train_rows: 40806`, 3 epoch, POSTER 특화, `model.safetensors` 442MB. 4개월치
작업물이다. 모바일에도 얹을지 판단해야 했는데, `meta.json` 어디에도 **규칙 대비
얼마나 나은지가 없다**. 그래서 직접 쟀다.

## 어떻게 쟀나

정답 라벨(`_verified: true`) 155장. **분류기만 바꾸고 나머지는 그대로 뒀다** —
값 정제(`extract_clean_value`)와 집계(`_aggregate`)는 규칙 파이프라인의 것을
그대로 쓴다. 후처리까지 다르면 무엇이 차이를 만들었는지 알 수 없다.

모델 입력은 학습과 동일한 형식이다(`build_dataset.py:117`):

```
[DOCTYPE=POSTER] [CTX] prev [TGT] cur [CTX] next
```

채점은 회귀 게이트(`server/ocr/tools/bench_posters.py`)와 같은 기준 —
정확률 = (정확 + 부분) / 정답보유.

## 결과

| title | 61.0% | 43.5% | 61.0% | −17.5 |
| organizer_name | 29.6% | 40.8% | **44.1%** | **+11.2** |
| event_start_date | 71.9% | 22.9% | 72.5% | −49.0 |
| event_end_date | 76.0% | **3.9%** | 76.0% | **−72.1** |
| contact_phone | 56.6% | 34.5% | 58.4% | −22.1 |
| contact_email | 60.7% | 60.7% | 61.7% | ±0.0 |
| location | 1.8% | 5.4% | 4.5% | +3.6 |
| website_url | 35.7% | 17.1% | 35.7% | −18.6 |

하이브리드 = 규칙이 채운 값을 우선하고 **빈 필드만** ML 로 메우는, 가장 보수적인 결합.

**ML 단독은 8필드 중 6필드에서 규칙보다 나쁘다.** 특히 날짜에서 무너진다 —
종료일은 154건 중 146건을 비웠다(3.9%). 날짜는 문맥 이해보다 정규식이 잘하는
일이고, 규칙이 이미 76% 다.

웹 팀 자체 기록(`eval/ocr_mod/ml/_poster_field_compare.json`, 27장)도 같은
방향이다: ML 단독 제목 0 / 날짜 30 / 장소 14 / 연락처 83, 하이브리드 33 / 100 /
86 / 83. 표본과 채점 기준은 다르지만 **ML 단독이 날짜에서 무너진다**는 결론은
독립적으로 재현됐다.

## 왜 도입하지 않는가

ML 이 의미 있게 나은 필드는 **주최기관 하나**다(+11.2%p, 하이브리드 +14.5%p).
그 한 필드를 위해 치러야 하는 비용:

- `model.safetensors` 442MB + torch 런타임. 이미지 크기와 콜드스타트가 함께 는다.
- 현재 Cloud Run 피크 RSS 956MB / 2Gi. 여유 1194MB 인데 klue/bert-base 로드만
  500MB 이상 든다. `--concurrency 4` 에서 안전 여유가 사라진다.
  (참고: 문서 종류 분류기는 ONNX 로 낮춰 +56MB 로 들어갔다.)
- 하이브리드는 누락을 50건 줄이는 대신 **오답을 21건 늘린다**. 빈 칸은 사용자가
  채우지만, 틀린 값은 못 알아채고 저장된다.

## 대신 한 것

ML 이 맞추고 규칙이 틀린 주최기관 36건을 열어 보고, 원인을 규칙으로 흡수했다
(커밋 `b656050`):

- 라벨·문장이 값이 되던 경로 차단 — '주최-주관기관'(표 헤더),
  '저작권은 주최측이가지며'(안내 문구)
- 중앙부처·지자체·군부대·학교 형태 추가 — 기후에너지환경부, 용인특례시,
  해군 제1함대사령부, 시흥시청소년수련관

결과 29.6% → 30.9%. **ML 하이브리드의 +14.5%p 에는 못 미친다.** 차이는 ML 이
앞뒤 블록을 문맥으로 본다는 데서 온다. 규칙으로 문맥을 흉내내려면 섹션 라벨과
값을 잇는 레이아웃 규칙이 필요하고, 그것은 날짜에서 이미 한 일이다
(`_reassign_poster_dates`) — 주최기관으로 확장하는 것이 ML 도입보다 값싼 다음 수다.
